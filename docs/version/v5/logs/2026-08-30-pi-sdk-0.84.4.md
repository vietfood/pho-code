# Pi SDK pin 0.84.1 → 0.84.4

Date: 2026-08-30
Owner: version/v5 (Pho Agent runtime pin) plus living architecture
Status: pin landed; unit and integration verified 2026-08-30; desktop/packaged not run
Related: startup investigation [`../../../urgent/2026-08-30-startup-pi-core-load.md`](../../../urgent/2026-08-30-startup-pi-core-load.md); compaction API-authority note [`../../../features/compaction/logs/2026-08-30-pi-pin-0.84.4.md`](../../../features/compaction/logs/2026-08-30-pi-pin-0.84.4.md)

## Intent

Move the exact Pi SDK pin to the current npm latest (`0.84.4`) so Pho Agent and Pho Code use installed typings that match upstream, including session JSONL trailing-newline repair, mid-run compaction of large tool results, and `session_compact_failed` / `ui_prompt_*` extension events. This is the reviewed pin change V4's plan allowed; it does not resume blocked V5 slices.

## Affected contracts

- `@pho-agent/runtime` dependencies: `@earendil-works/pi-coding-agent`, `pi-ai`, `pi-agent-core` exact `0.84.4`
- `INTENDED_PI_SDK.version` in `@pho-code/protocol`
- living architecture, development, V4/V5, compaction, and terminal pin sentences
- package-boundary, notices, and packaged-spec assertions

## Compatibility checked against 0.84.2–0.84.4

- Session construction remains `createAgentSessionRuntime` / `createAgentSessionServices` / `createAgentSessionFromServices`.
- Default active tools remain `read`, `bash`, `edit`, `write`. `createPowerShellTool` exists for Windows `defaultTools` and is not registered by `createCodingTools`.
- `GoogleThinkingLevel` → `GoogleApiThinkingLevel` is unused by this tree.
- `handleAgentEvent` already `default: return`s unknown Pi session events, so new compaction/UI-prompt events do not fail the host.
- Permission package peer `>=0.79.0` and `pi-cursor-sdk` peer `*` admit `0.84.4`.
- `engines.node` remains `>=22.19.0`; Electron `43.4.0` still embeds Node `24.18.1`.
