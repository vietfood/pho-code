## Intent

Give the owner a Settings surface to enable the OS box and run agent `bash` under Seatbelt in a real Electron window, so the wrap can be reviewed without waiting on skip-ask.

## Contracts and files

- Product: [`../product.md`](../product.md)
- Protocol: `packages/protocol/src/sandbox.ts`; `HarnessSettingsSnapshot.sandbox`; command `updateSandboxSettings`
- Persist: `{applicationDataDir}/sandbox-settings.json` via `packages/runtime/src/sandbox-settings.ts`
- Runtime: idle-only apply in `createPhoCodeRuntime`; factory always attached; **bash is replaced only while enabled**; disable rebinds idle sessions so built-in bash stays permission-gated
- UI: Settings section **Sandbox** after Permissions
- Electron: `updateSandboxSettings` IPC; Homebrew-less `PATH` still uses staged `rg` under `apps/desktop/resources` (do not point `PHO_CODE_RESOURCES_DIR` at an rg-only fixture)
- Not in this milestone: permission skip (M2), file-tool intercept (M3), `package:mac` staging (M4)

## Changes and decisions

- Settings-owned policy: enable, deny vs allowlist domains, registry-defaults toggle, extra read/write paths. `"*"` rejected in protocol and again in application/runtime.
- Idle-only like permissions: `hasAnyActiveRun()` throws `sessionBusy`. No queue. UI disables controls while a run is live.
- Persist under application data, not Pi JSONL and not AppMetadata (domain/path lists would otherwise copy through every workspace remember).
- Enable with no workspace stays `starting` until `session_start` or a later apply with cwd. Failed init still `failed` and blocks bash.
- Renderer snapshot includes honesty copy and owner-typed paths/domains. No proxy ports, Seatbelt profiles, or `rg` paths.
- Permission asks for bash may still appear while sandbox is on. This slice is reviewable Settings + wrap, not skip-ask.
- Enable/disable reloads idle session extensions so the bash wrap is installed only when Settings says on.

## Mistakes and corrections

Disabled factory originally used `createBashTool(process.cwd())`, which would have been Electron's app cwd instead of the session workspace. Disabled bash is no longer replaced: the factory `registerTool`s only while enabled, and `updateSandboxSettings` reloads idle sessions.

Always `registerTool`ing bash, even when sandbox was off, skipped permission asks in Electron (the replacement tool did not go through the permission dock). Node runtime tests still prompted, so the skip was easy to miss. Skip-ask remains Milestone 2.

Pointing `PHO_CODE_RESOURCES_DIR` at an rg-only temp fixture switched `resolveDesktopResourceLocator` to a packaged locator on that tree, so the permission extension did not load. The Electron journey now stages `rg` into `apps/desktop/resources` and strips Homebrew from `PATH` without overriding the locator.

The first Electron helper treated a live “Working for Ns” work-log toggle as settled and timed out while a permission dock was still up. It now waits for settled copy or dismisses each dock.

`bun run dev` from an agent shell failed immediately with `The requested module 'electron' does not provide an export named 'BrowserWindow'` because `ELECTRON_RUN_AS_NODE=1` made electron-vite launch main as Node 24. Playwright already deletes that variable; interactive launch needs `env -u ELECTRON_RUN_AS_NODE bun run dev`. A later launch with it unset started Electron and the renderer helper.
