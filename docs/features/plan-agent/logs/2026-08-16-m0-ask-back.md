## Intent

Ship juicesharp-style `ask_user_question` in ordinary Agent chat so the owner can pick A/B/C or Type something before Plan mode exists.

## Contracts and files

- Product: [`../product.md`](../product.md)
- Protocol: `HostDialogKind` `"questionnaire"`, `packages/protocol/src/plan-agent.ts`
- Runtime: `packages/runtime/src/plan-agent-feature.ts`, `ask-user-question.ts`, `ask-user-present.ts`, `ask-user-rpc-fallback.ts`, `extension-host.ts`
- UI: `packages/ui/src/ask-user-card.tsx` (feature-owned card; conversation chrome still owns the dock host)
- Desktop: `apps/desktop/tests/ask-user.spec.ts`

## Changes and decisions

- Pho-owned inline factory `plan-agent` `0.1.0` in the default manifest. Tool name `ask_user_question`. Do not bake `@juicesharp/rpiv-ask-user-question` or `pi-tui`.
- 8 KiB preview/note/custom fields **reject** (`text_too_long`), not truncate.
- Prefer `ui.questionnaire()` card; sequential `select`/`input` walker only if the card is missing or returns `undefined`. Card throw without a walker is host failure (“never saw”), not decline.
- Abort, session switch, quit, and Escape cancel with decline string `"User declined to answer questions"`.
- `custom` / `editor` still throw. One pending dialog at a time. Questionnaire chrome is not “Pending approval”.
- Permission presets allow `ask_user_question`. Deterministic test-model sessions must list the tool in the Pi `tools` allowlist or Pi never activates it.
- Plan/Agent toggle, Plan sidebar, and `todo` remain Milestone 1/2.

## Mistakes and corrections

- First integration dump showed `plan-agent` loaded but no tool in the context-prompt list. The schema was not the cause. Deterministic sessions pass an explicit `tools` allowlist that omitted `ask_user_question` (same reason `web_search` is absent in that lane).
- Transcript blocks use the display name `ask user`, not the canonical tool name.
- Playwright `.check()` on `sr-only` radios fails when the taller option label intercepts clicks. The spec clicks the option row.

## Owner feedback
