## Intent

Register a Cursor-style `todo` tool that works in Agent without opening Plan. The same list appears on the Plan surface and is injected on Execute when remaining items exist.

## Contracts and files

- Product: [`../product.md`](../product.md) Session todos
- Protocol: `TODO_TOOL_NAME`, `parsePlanTodoList`, snapshot `plan.todos` / `remainingCount`
- Runtime: `todo-tool.ts` merge-replace + `getBranch()` reconstruct; factory always unions `todo`; Execute hidden context prefers remaining todos
- UI: composer `n/m` chip, Plan sidebar checklist, transcript todo tool row

## Changes and decisions

- Tool name is `todo` (not `todo_write`). The call replaces the whole list. `todos: []` clears it.
- Persist is tool-result `details.todos` on the current Pi branch, not a second JSONL custom entry. `[DONE:n]` in assistant prose is ignored.
- At most one `in_progress` item; 50 items; 200 characters per content. Invalid calls return a structured error and leave the previous list.
- Completing every remaining item during Execute persists `executing: false` and mode Agent.
- Permission presets allow `todo` the same way as ask-user. YOLO still does not restore Plan write tools.
