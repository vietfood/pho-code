## Intent

When sandbox blocks a tool, the tool error should say why and tell the agent to stop. The owner changes Settings (turn sandbox off, or add a path/domain) and then tells the agent to continue. No retry-without-sandbox control, no system-prompt injection, no silent unsandbox.

## Contracts and files

- Product: [`../product.md`](../product.md) user-visible contract and permission-asks row
- File-tool reasons: `packages/runtime/src/sandbox-policy.ts`
- Bash OS/network annotation: `packages/runtime/src/sandbox-runtime.ts` `bashOperations().exec`
- Unavailable bash: `agentBashUnavailableMessage` appends the same owner-action instruction
- Not in this slice: Codex-style unsandbox retry, per-turn system prompt, packaged staging (M4)

## Changes and decisions

- Shared owner-action copy: do not retry; ask the owner to use Settings → Sandbox; wait until they say continue.
- Outside-policy file tools can be fixed with an extra path or by turning the box off. Protected paths (`~/.ssh`, `.env`, keys, engine-blocked files) cannot be added as extra roots.
- Healthy Seatbelt bash that fails with OS or network-deny text gets the same footer appended to streamed output. Ordinary failures (`command not found`) are left alone.
- Enabled-and-failed bash still throws; the message now tells the agent to ask the owner to turn the box off or fix the dependency.
